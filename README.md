# Комплект — подготовка документов для патента

Учебный проект по дисциплине «Проектирование информационных систем», команда **«ААА»**, group02. Задание **№ 5**, локальный раздел «Подготовка документов для патента», пункты 5.1–5.3. Лабораторная № 6 — работающее приложение с базой данных и видеоотчётом.

Сервис рассчитывает индивидуальный перечень: документ о знании русского языка, истории и законодательства России, цветные фотографии 3 × 4 см и ИНН. Заявитель подаёт комплект, специалист проверяет его, при необходимости запрашивает исправления и выдаёт заключение о комплектности. Экзамен, изготовление фотографий, получение ИНН и выдача патента происходят вне сервиса. Предметные условия используются как условия учебной модели.

## Инструкция по запуску

Нужны **Python 3.12 или новее** и современный браузер. Сторонние пакеты, Node.js и отдельный сервер БД для работы приложения не требуются.

Из корня репозитория:

```powershell
python solution/app.py
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). В Windows при необходимости замените `python` на `py -3.12`. Остановка сервера — `Ctrl+C`.

### База данных

При первом запуске автоматически создаются каталог `solution/data/`, база SQLite `solution/data/patent.sqlite3`, таблицы из `solution/schema.sql` и учётная запись специалиста. Запуск из другого каталога не меняет путь к базе по умолчанию. Миграции и ручное заполнение таблиц не нужны для первой установки.

Сведения пользователей, SMS-запросы, сеансы, анкеты, индивидуальные перечни, **содержимое файлов**, проверки, оценки, запросы дополнения, заключения и история находятся в БД. Принятые версии и старые документы сохраняются после дополнения, выхода и перезапуска сервера. База с персональными данными исключена из Git; после скачивания репозитория создаётся новая пустая база с учётной записью специалиста.

Чтобы выбрать другой порт или отдельную базу:

```powershell
python solution/app.py --port 8001 --db solution/data/another.sqlite3
```

Для резервной копии остановите сервер и скопируйте файл БД. Для демонстрации с чистыми данными используйте новый путь `--db`, сохранив прежнюю базу.

### Вход и роли

| Роль | Телефон | Вход |
| --- | --- | --- |
| Заявитель | Собственный учебный номер, например `+79991234567` | Вкладка «Регистрация», запрос кода, код `123456`. Затем вкладка «Вход» |
| Специалист по проверке комплекта | `+79990000001` | Вкладка «Вход», запрос кода, код `123456` |

SMS эмулируется: код показывается на экране, действует 5 минут, до 5 неверных попыток. Повторный запрос возможен через 2 секунды. Регистрация не позволяет выбрать роль специалиста. Сеанс действует 24 часа; выход отзывает его в БД. Телефон вводится с `+` и кодом страны; пробелы, скобки и дефисы допустимы.

Можно предварительно создать другого специалиста при запуске:

```powershell
python solution/app.py --specialist-phone +79990000002
```

Телефон должен быть свободен или уже принадлежать специалисту. Роль существующего заявителя не изменяется. Для второго одновременного участника используйте другой браузер или отдельный профиль, чтобы сеансы не заменяли друг друга.

## Сценарий работы

1. **Заявитель** регистрируется, открывает «Подать заявку», заполняет анкету и нажимает «Показать индивидуальный перечень». По учебным условиям услуга применима к гражданам Азербайджана, Таджикистана, Узбекистана, Молдовы и Украины без статуса ВКС и участника программы переселения. Неприменимая анкета не создаёт заявку.
2. Заявитель прикладывает доступные PDF, PNG или JPEG и отправляет заявку. До 5 МБ на файл, 12 файлов и 15 МБ на версию; проверяются расширение, тип и сигнатура формата. Отсутствие ещё не полученного документа допустимо. При заявленном наличии ИНН нужно указать 12 цифр; отдельное вложение ИНН необязательно. Контрольная сумма ИНН и подлинность документов автоматически не проверяются.
3. **Специалист** открывает обращение в очереди, начинает проверку, скачивает вложения и оценивает пункты 5.1–5.3. Можно сохранить неполную оценку или все оценки без решения: заявка остаётся «На проверке».
4. При недостатках специалист сохраняет три оценки, хотя бы одну «Требует исправления» с комментарием, затем вводит инструкции и нажимает «Запросить дополнение».
5. **Заявитель** открывает замечания, выбирает «Дополнить заявку», исправляет анкету и прикладывает новые документы. Нужные прежние файлы отмечает для сохранения. Отправка создаёт новую версию и возвращает заявку в «Подана»; предыдущая версия доступна в архиве.
6. **Специалист** начинает отдельную проверку новой версии, сохраняет соответствие всех трёх пунктов, вводит текст и выдаёт заключение. При новых недостатках возможен ещё один цикл дополнения.
7. **Заявитель** получает заключение, видит полную историю статусов и находит результат в «Оказанные услуги». Документы всех принятых версий доступны для скачивания.

Статусы согласованы с диаграммами: **Подана → На проверке → Требует дополнения → Подана → На проверке → Завершена**. Если недостатков нет, из «На проверке» сразу выдаётся заключение. Завершённое обращение не редактируется; можно подать новое.

## Устройство программы

| Файл | Назначение |
| --- | --- |
| `solution/app.py` | Локальный HTTP-сервер, маршруты, проверка сеанса, роли, источника запроса и CSRF |
| `solution/domain.py` | `Application`, `Review`, `Questionnaire`, `ChangeSet`, `ChecklistPolicy`, `SupplementValidator`; предметные ограничения |
| `solution/services.py` | `SessionService`, `SubmissionService`, `SupplementController`, `SupplementService`, `ReviewService`, `ApplicationQueryService` |
| `solution/repository.py` | `ApplicationRepository`: чтение, блокировка, атомарное сохранение и откат |
| `solution/schema.sql` | Десять предметных таблиц ER-модели и технические таблицы сеансов/SMS-запросов |
| `solution/static/` | Адаптивные экраны заявителя и специалиста, в том числе `SupplementForm` |
| `solution/tests/` | Проверки HTTP-сценариев и воспроизводимая браузерная демонстрация |

Предметные записи `ApplicationVersion`, `Document`, `Finding` и другие небольшие сущности диаграммы представлены именованными полями словарей, загружаемых репозиторием. Анкета — объект значения, её снимок хранится как JSON в версии. Это реализация логической модели без отдельного класса для каждой строки SQLite.

В Python методы, аргументы и поля объектов используют `snake_case`. Ключи JSON и столбцы SQLite сохраняют `camelCase`; `Questionnaire.to_payload()` явно преобразует анкету в этот формат. Чтение HTTP-запроса, проверка вложения и сохранение частей заявки выделены в небольшие методы.

В SQLite `BEGIN IMMEDIATE` блокирует запись до повторной проверки состояния и единого `commit`. Все изменения заявки соблюдают этот порядок. Уникальные ограничения исключают два ответа на запрос и повторный номер версии. При дополнении выбранные файлы копируются в новую версию с новыми идентификаторами. При оценке/решении проверяется ревизия проверки, чтобы устаревшая вкладка не перезаписала новую оценку. После неопределённого исхода сохранения нужно повторно открыть заявку и проверить версию/историю.

Приложение работает на `127.0.0.1` для учебной демонстрации, использует постоянный SMS-код и не подключено к государственным системам. Стек выбран командой для lab06, а не предписан преподавателем.

## Проверки

Из корня репозитория, без дополнительных пакетов:

```powershell
python -m unittest discover -s solution/tests -v
```

Проверяются полный цикл с дополнением, сохранение после перезапуска, скачивание старых и новых файлов, запрет чужого доступа, роли, отзыв сеанса, ошибочный SMS-код, CSRF, неприменимость, некорректные файлы и анкеты, устаревшие оценки, повторное и конкурентное дополнение, полный откат при искусственной ошибке записи. Тесты создают изолированные базы в игнорируемом каталоге `solution/.artifacts/`.

Браузерный сценарий дополнительно проверяет обе роли, формы, архивные версии, скачивание и узкий экран 390 px. Для его повторения нужны дополнительные **инструменты разработки**, которые не требуются приложению:

```powershell
python -m pip install -r solution/requirements-dev.txt
python -m playwright install ffmpeg
python solution/tests/browser_demo.py
```

Сценарий использует установленный Google Chrome по стандартному пути Windows. При другом расположении измените `executable_path` в сценарии. Для повторной записи видео: `python solution/tests/browser_demo.py --record`; существующий `report/lab06-demo.mp4` будет заменён новой записью. При наличии локальных инструментов в `solution/.tools/browsers` сценарий использует их; иначе — стандартную установку Playwright.

### Срок исполнения

По заметке пользователя со встречи с преподавателем в интерфейсе показан срок исполнения. Продолжительность выбрана командой для учебной модели: 3 календарных дня с первоначальной подачи, без приостановки на дополнение и без переноса после него. Это не нормативный срок государственной услуги. Дата рассчитывается из сохранённой даты подачи, доступна обеим ролям в списке и карточке, в том числе для прежних заявок; время отображается по Екатеринбургу (UTC+5). Незавершённые заявки после срока помечаются «Срок истёк».
