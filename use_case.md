# Лабораторная работа № 1. Диаграмма прецедентов

```mermaid
usecase-beta
direction LR
actor User("Пользователь системы")
actor Applicant("Заявитель")
actor Specialist("Специалист по проверке комплекта")

systemBoundary "Сервис подготовки документов для патента"
  Register("Зарегистрироваться по телефону")
  Login("Войти по телефону и SMS-коду")
  ConfirmPhone("Подтвердить телефон кодом")
  Submit("Подать заявку на подготовку комплекта")
  Determine("Определить индивидуальный перечень документов")
  Validate("Проверить корректность анкеты и вложений")
  Checklist("Просмотреть индивидуальный перечень документов")
  Supplement("Дополнить заявку по запросу специалиста")
  Track("Просмотреть статус и историю заявки")
  Result("Получить результат проверки комплекта")
  Archive("Просмотреть ранее завершённые заявки")
  Review("Проверить заявку и приложенные документы")
  Compare("Сопоставить комплект с индивидуальным перечнем")
  Request("Запросить исправления и недостающие документы")
  Complete("Завершить проверку и выдать результат")
end

Applicant --|> User
Specialist --|> User
User -- Login
Applicant -- Register
Applicant -- Submit

Applicant -- Supplement
Applicant -- Track
Applicant -- Result
Applicant -- Archive
Specialist -- Review

Register ..> : include ConfirmPhone

Submit ..> : include Validate
Submit ..> : include Determine
Supplement ..> : include Validate
Supplement ..> : include Determine
Review ..> : include Compare
Request ..> : extend Review
Complete ..> : extend Review

note for Review "Точка расширения: решение по проверенному комплекту"
note for Request "Условие: выявлены недостатки"
note for Complete "Условие: все применимые пункты выполнены"
```

## Границы системы и роли

Тема — раздел 5 «Подготовка документов для патента», пункты 5.1–5.3. Система помогает определить нужные документы, собрать их в заявке и получить результат проверки комплекта. Заявитель работает только со своими заявками. Специалист просматривает поступившие заявки, проверяет сведения и вложения, запрашивает дополнения и фиксирует результат.

Заявитель и специалист — две конкретные роли. «Пользователь системы» — их общий актор для входа, а не третья роль приложения. Обобщение означает, что оба конкретных актора наследуют участие во входе; оно не передаёт заявителю полномочия специалиста.

Две роли и проверка комплекта специалистом — принятые для черновика решения учебной модели, а не явно заданный преподавателем процесс. Подтверждение границ темы преподавателем пока не зафиксировано.

Экзамен, изготовление фотографий и получение ИНН происходят вне системы. Она не выдаёт сертификат или ИНН, не принимает заявление на сам патент и не решает вопрос о его выдаче. Образовательная организация, фотостудия и ФНС не показаны как акторы: в этой модели они не взаимодействуют с приложением. Заявитель самостоятельно получает документы и прикладывает их копии.

## Содержание прецедентов

| Прецедент | Действия и результат |
| --- | --- |
| Зарегистрироваться по телефону | Заявитель указывает телефон и подтверждает его кодом. Создаётся учётная запись заявителя; назначение роли специалиста через публичную регистрацию не допускается. |
| Войти по телефону и SMS-коду | Участник подтверждает телефон и получает доступ к действиям своей роли. В учебном приложении допустим постоянный код `123456`; реальные SMS не обязательны. Учётная запись специалиста создаётся заранее. |
| Подтвердить телефон кодом | Общее обязательное поведение регистрации и входа: участник вводит полученный код, система проверяет его. Неверный код не позволяет завершить регистрацию или вход. |
| Подать заявку на подготовку комплекта | Заявитель заполняет анкету: гражданство, наличие статуса высококвалифицированного специалиста или участника программы переселения, документа о знании языка, истории и законодательства, а также ИНН. Прикладывает имеющиеся документы и отправляет заявку. Система сохраняет её и определяет индивидуальный перечень. |
| Просмотреть индивидуальный перечень документов | Заявитель видит, какие из трёх пунктов применимы к его анкете, что уже имеется и что нужно получить вне системы. |
| Определить индивидуальный перечень документов | Обязательная часть подачи и дополнения заявки: система применяет условия 5.1–5.3 к актуальной анкете. При исправлении анкеты перечень пересчитывается. Результат сохраняется вместе с принятой версией заявки. |
| Проверить корректность анкеты и вложений | Общая обязательная часть подачи и дополнения: система проверяет обязательные поля, допустимые значения и формат приложенных файлов. Это формальная проверка, а не оценка комплектности специалистом. Отсутствие ещё не полученного документа допускает подачу; некорректные поля или файлы нужно исправить до отправки. |
| Дополнить заявку по запросу специалиста | При наличии запроса заявитель исправляет сведения и прикладывает недостающие или исправленные документы, затем направляет заявку на повторную проверку. |
| Просмотреть статус и историю заявки | Заявитель видит текущее состояние, изменения с датами и комментарии специалиста по своей заявке. |
| Получить результат проверки комплекта | После завершения проверки заявитель открывает заключение специалиста о комплектности и соответствии приложений условиям учебной модели. Это не решение государственного органа о выдаче патента. |
| Просмотреть ранее завершённые заявки | Заявитель открывает список своих завершённых обращений, их документы, историю и результаты. |
| Проверить заявку и приложенные документы | Специалист выбирает поступившую заявку и сопоставляет анкету и вложения с индивидуальным перечнем. |
| Сопоставить комплект с индивидуальным перечнем | Обязательная часть проверки специалистом: по каждому применимому пункту оцениваются наличие и соответствие документа, фиксируются выявленные недостатки либо их отсутствие. |
| Запросить исправления и недостающие документы | Если обнаружены недостатки, специалист сохраняет конкретный список замечаний. Заявка становится доступна заявителю для дополнения. |
| Завершить проверку и выдать результат | Если все применимые пункты выполнены, специалист сохраняет заключение и завершает заявку. Результат доступен заявителю. |

## Семантика связей

Сплошные линии без стрелок — ассоциации участия акторов. Стрелки с пустым треугольником направлены от конкретного актора к общему. Зависимости между прецедентами имеют следующий смысл:

| Связь | Обоснование |
| --- | --- |
| Регистрация / вход `include` подтверждение телефона | В обоих сценариях подтверждение кодом обязательно. Стрелка направлена к включаемому прецеденту. |
| Подача / дополнение `include` проверку корректности | Каждая отправляемая версия проходит одну и ту же формальную проверку данных. Ошибки останавливают отправку. |
| Подача / дополнение `include` определение перечня | Перечень обязательно рассчитывается по актуальной анкете, в том числе после её исправления. |
| Проверка заявки `include` сопоставление комплекта | Без оценки документов по применимым пунктам цель проверки не достигается. |
| Запрос исправлений `extend` проверку заявки | В точке «решение по проверенному комплекту» при выявленных недостатках специалист оформляет запрос и переводит заявку в состояние «Требует дополнения». Стрелка направлена от расширения к базовой проверке. |
| Завершение и выдача результата `extend` проверку заявки | В той же точке при выполнении всех применимых пунктов специалист оформляет итоговое заключение и переводит заявку в состояние «Завершена». Условие взаимоисключающее с запросом исправлений. |

Базовая проверка имеет самостоятельный результат: сохранённую оценку комплекта. Она может закончиться без оформления запроса или итогового заключения; тогда заявка остаётся «На проверке», и специалист позже возвращается к ней. Условные расширения выполняются при выборе соответствующего действия специалистом после оценки. Поэтому обязательное поведение проверки вынесено в `include`, а два возможных решения — в `extend`.

Вход — предусловие работы с заявками: включать повторный вход в каждый прецедент не требуется. Дополнение заявки — самостоятельная цель заявителя в другой сессии, доступная только в состоянии «Требует дополнения». Между запросом специалиста и дополнением заявителя нет `extend`: эта зависимость выражается предусловием, а не продолжением одного выполнения. Получение результата доступно только после завершения заявки. Ассоциации и зависимости не задают временной порядок; цикл работы описан ниже текстом.

## Предусловия и результаты основных целей

| Цель | Предусловие | Успешный результат / альтернативный исход |
| --- | --- | --- |
| Подать заявку | Заявитель вошёл в систему | Корректная анкета и применимый перечень сохранены, заявка получила состояние «Подана». При ошибках система показывает их и не отправляет заявку; при неприменимости пунктов объясняет причину и не создаёт заявку на проверку. |
| Проверить заявку | Специалист вошёл; заявка подана либо уже находится у него на проверке | Заявка находится «На проверке», оценка комплекта сохранена. В точке расширения специалист может запросить исправления либо выдать результат при выполнении соответствующего условия. |
| Дополнить заявку | Заявитель вошёл, заявка принадлежит ему и имеет состояние «Требует дополнения» | Исправленная версия и пересчитанный перечень сохранены, заявка снова «Подана». При формальных ошибках остаётся «Требует дополнения». |
| Получить результат | Заявитель вошёл, его заявка завершена | Открыто сохранённое заключение по комплекту; документы и история остаются доступны. |

## Правила индивидуального перечня

Правила ниже воспроизводят условия задания как учебную модель и не являются правовой консультацией.

Общее условие применения пунктов 5.1–5.3: гражданство Азербайджана, Таджикистана, Узбекистана, Молдовы или Украины и отсутствие обоих статусов — высококвалифицированного специалиста и участника программы переселения.

- **5.1. Сертификат:** получить сертификат нужно, если нет документа, подтверждающего знание русского языка, истории России и основ законодательства РФ. При наличии подходящего документа заявитель прикладывает его вместо получения нового сертификата. Срок из задания — до подачи заявления на патент.
- **5.2. Фотографии:** при общем условии нужны цветные фотографии 3 × 4 см.
- **5.3. ИНН:** получать ИНН нужно при общем условии и его отсутствии. Уже имеющийся ИНН заявитель указывает в анкете.

Если общее условие не выполнено, система сообщает, что пункты 5.1–5.3 по условиям задания не применяются, и не отправляет пустой комплект специалисту. Это не означает, что человеку не нужны другие документы: они находятся вне выбранной темы.

## Основной сценарий и состояния

Заявитель входит, заполняет анкету и отправляет заявку с имеющимися приложениями. Система сохраняет индивидуальный перечень. Специалист начинает проверку. При недостатках он запрашивает дополнения; заявитель исправляет заявку и направляет её повторно. Когда комплект соответствует применимым пунктам, специалист завершает проверку, а заявитель получает заключение и впоследствии может открыть завершённую заявку.

Рабочие состояния для согласования следующих этапов: «Подана» → «На проверке» → «Требует дополнения» → «Подана»; из состояния «На проверке» возможен переход в «Завершена». Каждый переход сохраняется в истории с датой и инициатором. Эти состояния — решение проекта, а не дополнительные требования курса.
